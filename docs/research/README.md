# Research (30 October 2026)

Four reports written before the product was designed, each with sources inline.

| report | what it answers | what it changed in the design |
|---|---|---|
| [market-landscape.md](market-landscape.md) | Who sells a "software factory" in 2026 (Factory, Devin, Codex, Claude Code cloud, Copilot coding agent, Cursor, Jules, Kiro, Rovo Dev, GitLab Duo, Tembo, OpenHands…), how they take work in, how they report, what they cost, how they perform (SWE-bench Pro ≈ 58–59%, agent-PR merge rates 43–83% and confounded, DORA 2025: more throughput, more instability). | The adapter sits at the **harness** level (Claude Code / Codex / Gemini CLIs), not under Claude Code. Intake from any tracker; outcome telemetry per task (cost, first-pass rate, lead time); PR babysitting including failing checks. |
| [operating-model.md](operating-model.md) | What "software factory" has meant (Microsoft, DoD, lean), how teams that run agents at scale structure the loop, where it fails (review bottleneck, prompt injection, test tampering, runaway loops, destructive actions), and a concrete operating model. | Review capacity as the WIP limit (`maxInReview`); deterministic verify before AI review; capped fix rounds; worktree isolation and an allow-listed environment; kill switch; the book of notes; risk-tiered gates (`auto_low_risk`). |
| [claude-code-headless.md](claude-code-headless.md) | Exactly how `claude -p` 2.1.314 behaves: flags that exist, stream-json shapes, permissions without a TTY, settings precedence, cost vs. plan usage, resume, isolation, the Agent SDK, Codex/Gemini equivalents. | `--permission-prompts none`, `--setting-sources project`, `--strict-mcp-config`, never `--bare`; usage throttling from `rate_limit_event`; warn when `apiKeySource` is not the subscription; `--max-turns`/`--max-budget-usd` per run; session ids pinned so follow-ups resume. |
| [integrations.md](integrations.md) | Slack Socket Mode vs Events API vs polling (and the 2025 rate-limit change), Jira's `search/jql`, GitHub polling and checks, Linear's API and agents, pollers with catch-up, posting back, webhook verification, prompt-injection defences. | Socket Mode for Slack (no inbound URL), polling everywhere else, dedupe by source + external id, one status thread per request, decisions by comment (`approve` / `reject`). |
